3.4 SSL and HTTPS

  • SSL/TLS encryption mode: Full (strict) — set 14 August 2026.
  • Edge Certificates: Always Use HTTPS — On.

Do not use Flexible SSL (that would encrypt browser→Cloudflare only and can break cookies / mixed content).

3.5 Verification

First HAR export (before orange-cloud / propagation) showed server: nginx and no cf-ray on the HTML document. Traffic was still hitting Forge directly. Cloudflare headers on that file were only for R2 object storage URLs, not the website.

4. Decisions and guidance (no code in this session)

4.1 E-sign for 1,000+ NDAs — SignWell

Recommendation

For high-volume NDA signing, SignWell API was recommended over building a custom signer. Not implemented in code. Revisit when you are ready to connect templates, webhooks, and stored signed PDFs.

4.2 Public launch vs 10,000 concurrent users

Capacity

The LMS can launch publicly on the current Forge + Cloudflare setup for normal traffic. 10,000 concurrent video viewers is not supported on a single Forge app server if lessons stream from Laravel / R2 signed URLs through the origin.

Path to that capacity:

  1. Enable Bunny Stream in Admin → Settings → Bunny Stream.
  2. Re-upload older lessons so they get a bunny_video_id.
  3. Keep Cloudflare in front for HTML/assets; let Bunny (player.mediadelivery.net / b-cdn.net) carry video.
  4. Later: Redis, queue workers, and more than one app server if app traffic (not just video) grows.

Cloudflare empty analytics / “no requests in 24h” right after going Active is stats lag, not a broken proxy.

4.3 Autoplay with sound

Chrome, Safari, and mobile browsers will not autoplay with sound without a user gesture. A popup cannot legally bypass that. The implemented approach (muted autoplay + first tap to unmute) is the reliable pattern.

7. Suggested Cloudflare cache rules (not applied yet)

When you want them:

  • Cache: /, /faqs, /about-us, /courses*, static /build/*
  • Bypass (do not cache): /dashboard*, /play-course*, login/register, Stripe webhooks/checkout, Admin

Until then, Laravel’s Cache-Control: no-cache, private plus session cookies keep HTML as DYNAMIC. That is safe.
